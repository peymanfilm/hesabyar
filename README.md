# حساب‌یار

مدیریت آفلاین وام‌ها، اقساط بانکی، طلب‌ها و بدهی‌ها — کاملاً فارسی، RTL، تقویم شمسی.

- **پلتفرم هدف:** Android (APK release امضاشده)
- **شناسهٔ بسته:** `com.peymanfilm.hesabyar`
- **معماری:** React Native + Expo SDK 58 + TypeScript strict + Expo Router
- **داده:** فقط روی گوشی (expo-sqlite + Drizzle ORM) — بدون سرور، بدون اینترنت

## امکانات

- **وام و اقساط بانکی:** تولید جدول اقساط ماهانهٔ شمسی (مدیریت درست روزهای ۳۰/۳۱ و اسفند کبیسه)، پیش‌نمایش قبل از ثبت، ویرایش مبلغ/تاریخ هر قسط، پرداخت جزئی و چندپرداخت برای یک قسط، تسویهٔ کامل، رسید، ماندهٔ قسط/وام و پیشرفت تسویه
- **طلب و بدهی از اشخاص:** ماندهٔ خودکار با هر دریافت/پرداخت، تسویهٔ یک‌جا/قسطی/نامنظم، تاریخچه و رسید — طلب و بدهی هرگز خودکار تهاتر نمی‌شوند
- **تراکنش:** ثبت اتمیک تراکنش + تخصیص به حساب یا قسط، روش نقدی/کارت‌به‌کارت/انتقال بانکی/سایر، نمایش مانده پس از ثبت، رسید PDF و اشتراک‌گذاری
- **اشخاص:** پروندهٔ شخص با مجموع طلب، مجموع بدهی و خالص با جملهٔ واضح
- **خانه:** تعهدات ماه، مانده‌ها، پرداخت/دریافت ماه، نزدیک‌ترین سررسیدها، عقب‌افتاده‌ها، نمودار و ثبت سریع
- **گزارش‌ها:** ماهانه و سالانه شمسی، تفکیک به شخص و بانک، خروجی CSV سازگار با Excel و PDF فارسی RTL
- **یادآوری‌ها:** اعلان واقعی سیستم (روز سررسید و ۱/۳/۷ روز قبل)، تعویق، لغو پس از تسویه، باز شدن صفحهٔ مرتبط با لمس اعلان، بدون تایمر JavaScript
- **پشتیبان‌گیری:** فایل JSON نسخه‌بندی‌شده شامل داده و رسیدها، اعتبارسنجی کامل قبل از بازیابی، پشتیبان احتیاطی، بازسازی اعلان‌ها
- **تنظیمات:** تم روشن/تاریک/سیستم، واحد تومان/ریال (تغییر واحد ارزش داده را عوض نمی‌کند)، قفل بیومتریک اختیاری، حذف کامل اطلاعات

## نصب APK

1. از صفحهٔ [Release مخزن](../../releases) فایل `hesabyar-vX.Y.Z-android.apk` را دانلود کنید.
2. SHA-256 فایل را با مقدار کنار فایل مقایسه کنید (`sha256sum hesabyar-*.apk`).
3. در اندروید اجازهٔ نصب از منبع آن را بدهید و نصب کنید.
4. اپ بدون اینترنت، بدون Metro و بدون سرور توسعه اجرا می‌شود.

> حداقل نسخهٔ اندروید و معماری‌های هدف از خروجی prebuild تعیین می‌شود (Uni-apk شامل arm64-v8a و armeabi-v7a و x86_64).

## راه‌اندازی توسعه

پیش‌نیازها: Node.js 20+، npm، JDK 17 (برای build بومی)، Android Studio/SDK (فقط برای اجرای روی شبیه‌ساز محلی).

```bash
npm ci          # نصب با lockfile
npm start       # Metro / Expo dev server
npm run android # اجرای روی شبیه‌ساز (build بومی)
```

پروژهٔ بومی تولیدی است؛ هرگز دستی داخل `android/` تغییر ندهید — همهٔ تنظیمات از `app.config.js` و `plugins/` با `npx expo prebuild --platform android --clean` بازتولید می‌شوند.


## ساخت APK

```bash
# build آزمایشی debug (بدون امضای release)
npx expo prebuild --platform android --clean
cd android && ./gradlew assembleDebug

# build release امضاشده نیازمند متغیرهای محیطی امضا (همان Secrets در CI):
# HESABYAR_KS_FILE / HESABYAR_KS_PASS / HESABYAR_KS_ALIAS / HESABYAR_KS_KEY_PASS
cd android && ./gradlew assembleRelease
node scripts/verify-apk.mjs app/build/outputs/apk/release/app-release.apk
```

ساخت اصلی و رسمی در GitHub Actions انجام می‌شود (`.github/workflows/android-release.yml`) — بدون EAS Cloud یا سرویس پولی.

## تنظیم Secrets بدون افشای مقدار

در GitHub → Settings → Secrets and variables → Actions، چهار Secret زیر (مقادیر هرگز در کد/مستند/commit وارد نمی‌شوند):

| Secret | توضیح |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | خروجی `base64 -w0 hesabyar-release.keystore` |
| `ANDROID_KEYSTORE_PASSWORD` | رمز store |
| `ANDROID_KEY_ALIAS` | نام alias کلید |
| `ANDROID_KEY_PASSWORD` | رمز key |

جزئیات ساخت کلید: [docs/signing.md](docs/signing.md). workflow در نبود این Secrets عمداً شکست می‌خورد تا APK debug جا release نشود.

## نحوهٔ انتشار نسخهٔ بعدی

```bash
node scripts/bump-version.mjs 1.0.1   # به‌روزرسانی version و versionCode افزایشی
git commit -am "bump version 1.0.1"
git tag v1.0.1
git push origin main v1.0.1
```

workflow `android-release.yml` با تگ اجرا می‌شود: تست‌ها → build امضاشده → بررسی امضا و applicationId → نصب و اجرا روی شبیه‌ساز API 30 → انتشار draft Release پس از موفقیت همهٔ بررسی‌ها.

## اهمیت حفظ کلید امضا

- کلید ثابت برای به‌روزرسانی‌های آیندهٔ اندروید ضروری است؛ با کلید جدید، کاربران نمی‌توانند اپ را به‌روزرسانی کنند.
- نسخهٔ پشتیبان کلید را در جای امن خارج از مخزن نگه دارید (مدیر رمز، هارد رمزنگاری‌شده).
- کلید خصوصی هرگز داخل Git، Release یا artifact قرار نمی‌گیرد؛ فقط هنگام build در فضای موقت باز می‌شود و پس از آن پاک می‌شود.
- Base64 رمزگذاری امنیتی نیست؛ Secret فقط مانع افشا در لاگ/کد است.

## پشتیبان‌گیری و بازیابی

از تنظیمات → پشتیبان‌گیری و بازیابی:
- **ساخت پشتیبان:** فایل JSON نسخه‌بندی‌شده شامل همهٔ داده‌ها و رسیدها؛ اشتراک‌گذاری در محل دلخواه.
- **بازیابی:** اعتبارسنجی کامل ساختار و مبالغ پیش از هر تغییری؛ فایل خراب دادهٔ موجود را تخریب نمی‌کند؛ پیش از جایگزینی پشتیبان احتیاطی ساخته می‌شود.
- فایل پشتیبان **رمزگذاری نمی‌شود** — در محل امن نگه دارید.
- پس از بازیابی، اعلان‌ها با باز شدن دوبارهٔ اپ بازسازی می‌شوند.

## محدودیت اعلان‌ها

- اعلان‌ها با `expo-notifications` و شناسه‌های قطعی زمان‌بندی می‌شوند (بدون تکرار، بدون تایمر JS)؛ سقف اعلان‌های سیستم‌عامل با اولویت نزدیک‌ترین‌ها مدیریت می‌شود.
- اگر اپ **force-stop** شود یا بهینه‌ساز باتری سازنده زمان‌بندی را محدود کند، اعلان ممکن است به تأخیر بیفتد؛ این محدودیت اندروید است و در صفحهٔ یادآوری‌ها ذکر شده.
- روی بعضی سازنده‌ها باید مجوز «آلارم دقیق» را در تنظیمات گوشی فعال کنید.
